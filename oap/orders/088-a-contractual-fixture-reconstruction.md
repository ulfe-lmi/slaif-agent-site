## Contract and objective

Execute the contractual whole-site fixture reconstruction, previously and
incorrectly classified post-MVP. Links: §§9.3, 23, 42.6, 51.1, 52.4/52.6,
53.3. Requires 074–087.

## Required product proof

Start a clean source-fixture and Agent-Site Compose deployment. A human creates
one Level-4 workspace with that exact origin approved. An external agent/client:
inspects source only through 084 tools; discovers schemas/catalog; dynamically
creates suitable types/fields/items/relations/views, hierarchy/routes,
components/navigation/redirects/theme/media through supported REST/MCP; renders
workspace; runs responsive observations; uses evidence to make at least one
semantic iteration. No content model/site state is pre-baked. Human opens the
same composition in Puck, makes one visible adjustment, freezes/reviews the
immutable bundle and accepts. Canonical/public routes, content/media/navigation/
design and responsive coverage match the fixture acceptance manifest.

## Anti-bypass and negatives

No SQL, ORM, service/repository/internal API, privileged human data mutation,
filesystem injection, fixture state insertion or test-only helper may perform
claimed source/agent/Puck/review behavior. Neutral identities/site/catalog and
assertion-only reads are allowed. Prove source cannot escape origin, agent
cannot publish or change code/schema, canonical unchanged before human accept,
private evidence/media boundaries, schema/Alembic/repository unchanged, audit
complete and no hosted service.

Test must fail when dynamic model creation, source browser, real preview,
responsive iteration, Puck save, snapshot, promotion or public renderer is
removed. Run public NGINX, real DB/media/browser/review worker, desktop/tablet/
phone and required CI with retained evidence. Binary done is the complete
reconstruction lifecycle. Report `088-a-contractual-fixture-reconstruction.md`
with SELF; no merge/extra PR.
